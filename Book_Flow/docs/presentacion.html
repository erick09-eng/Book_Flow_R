Contexto

El problema que resolvemos

Los estudiantes y lectores necesitan una forma simple de organizar sus libros, hacer seguimiento de préstamos, guardar favoritos y compartir reseñas — sin complejidad innecesaria.

Catálogo desorganizado

Dificultad para buscar, filtrar y ordenar libros por género, autor, disponibilidad o calificación.

Sin seguimiento de préstamos

No hay control de fechas de devolución, renovaciones ni historial de libros prestados.

Reseñas sin persistencia real

Comentarios perdidos al recargar, sin validación, sin ownership, sin confianza en los datos.

Código legacy difícil de mantener

Vanilla JS monolítico, sin componentes reutilizables, sin testing, sin estructura escalable.

Migración

De Vanilla JS a React + Vite

Reescritura completa manteniendo la misma UX, añadiendo arquitectura escalable, testing y despliegue profesional.

Routing SPA

React Router v6: 7 rutas (/, /catalogo, /libro/:id, /acceso, /cuenta, /biblioteca, 404) con navegación fluida y recarga nativa.

Componentes reutilizables

Header, Footer, ProductCard, ModalRoot, Toast, Tabs, Forms — 100% reutilizables con props tipadas.

Auth real + RLS

Google OAuth → Supabase Auth → Row Level Security en tabla reviews. Datos protegidos a nivel BD.

Testing incluido

18 tests unitarios con node --test validando validateReview (rating 1-5, comment 10-300 chars).

Arquitectura

Arquitectura limpia por capas

Separación de responsabilidades: UI → Estado → Lógica → Datos → Externo

flujo-de-datos.txt 
┌─────────────────────────────────────────────────────────────────┐
│                      PRESENTATION LAYER                        │
│  Pages (Index, Catalogo, Detalle, Biblioteca, Cuenta, Acceso)  │
│  Components (Header, ProductCard, ModalRoot, Toast, Tabs...)   │
│  → JSX + CSS Modules + react-bootstrap Alert                   │
└──────────────────────────┬────────────────────────────────────┘
                           │ useContext / useHooks
┌──────────────────────────▼────────────────────────────────────┐
│                      STATE & LOGIC LAYER                       │
│  AppContext (sesión, modal, toast, refresh, signedIn/Out)     │
│  Hooks: useBookActions, useCatalogView, useLocale, useReviews │
│  → Lógica pura, testeable, sin UI                              │
└──────────────────────────┬────────────────────────────────────┘
                           │ import services
┌──────────────────────────▼────────────────────────────────────┐
│                      SERVICE LAYER                             │
│  bookService, loanService, favoriteService, usersService       │
│  reviewService (validateReview, filterReviews, averageRating)  │
│  supabaseService (API reseñas), googleService (OAuth)          │
└──────────────────────────┬────────────────────────────────────┘
                           │ localStorage / Supabase / Google APIs
┌──────────────────────────▼────────────────────────────────────┐
│                      DATA LAYER                                │
│  localStorage: loans, favorites, users, session, preferences   │
│  Supabase (PostgreSQL): reviews table + RLS policies           │
│  Google Identity Services: OAuth 2.0 Client ID                 │
└─────────────────────────────────────────────────────────────────┘
Single Responsibility: Cada hook/servicio hace una cosa (ej. useCatalogView solo maneja vista grid/list en localStorage)
React Router (pantalla) + RLS Supabase (datos): Dos capas de seguridad. La ruta protege la UI; la política RLS protege los datos.
Offline-first para datos propios: Préstamos y favoritos en localStorage (rápido, privado). Solo reseñas (compartidas) en Supabase.
CSS Variables + 1 CSS Module: Design system consistente (--color-*, --radius-*, --shadow-*) + Header como Module.
Features implementadas

Funcionalidades completas

Todo lo que pide la guía del 3er corte + extras de calidad

Catálogo inteligente

Búsqueda en tiempo real, filtros por género/rating/disponibilidad, orden A-Z/rating/recientes, paginación, vista Grid/List persistente en localStorage.

Detalle con URL propia

Ruta /libro/:id con loading, error + retry (3 intentos), "no disponible", enlace directo, volver al catálogo. Tarjetas enlazan con .

Reseñas CRUD + RLS

Crear/Leer/Actualizar/Borrar con validación (rating 1-5, comment 10-300 chars). Solo dueño edita/borra. Lectura pública. Filtro por texto + rating.

i18n con Intl nativo

useLocale hook: fechas formateadas según navigator.language (es-ES, en-US, fr-FR...). Números, moneda, rating localizados. Cero permisos.

Acceso + Sesión real

Página /acceso (login/registro/recuperar pass). Google OAuth. ProtectedRoute → /acceso. Context global. Logout limpia TODO (loans, favs, sesión).

Testing + Lint + Deploy

18 tests node --test. ESLint 9 + Prettier. vercel.json SPA rewrite. Variables VITE_* en Vercel. Supabase Redirect URL configurada.

Tech Stack

Tecnologías elegidas con criterio

Cada herramienta resuelve un problema concreto, sin over-engineering

React 18 + Vite 5

DX moderna, HMR instantáneo, build optimizado (dist/ 608KB JS gzipped). ES Modules nativos.

React Router v6

SPA routing declarativo, NavLink con isActive, Outlet para layout anidado, ProtectedRoute wrapper.

Supabase (PostgreSQL + Auth + RLS)

Base de datos real, Auth con Google OAuth, Row Level Security en tabla reviews. Cero backend propio.

@supabase/supabase-js v2

Cliente npm tipado, signInWithIdToken para sesiones RLS, tiempo real opcional.

Vercel (Hobby)

Deploy automático desde GitHub, vercel.json rewrite SPA, Env Vars VITE_*, preview deployments.

Intl API nativo (i18n)

Intl.DateTimeFormat, Intl.NumberFormat, navigator.language. Sin librerías extra, cero permisos.

react-bootstrap (solo Alert)

Componente en página Detalle para errores. Librería visual mínima, resto UI propia.

Node test runner nativo

node --test (v20+). 18 tests sobre validateReview. Sin Jest/Vitest. Zero config.
